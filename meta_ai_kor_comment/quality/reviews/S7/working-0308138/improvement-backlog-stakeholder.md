# Stakeholder 개선 백로그 — working-0308138

이 문서는 사람 의사결정자를 지원하는 AI 관찰이며 공식 사람 평가가 아니다. `formal_human_gate_eligible=false`이고 human ratings·score·attestation을 생성하지 않았다. 이전 사람 CSV, 이전 AI 점수, 이전 stakeholder 관찰은 검토하지 않았다.

`review-population.jsonl`의 921개 표시 결과를 검토했다. `result.xlsx`는 파일 존재와 메타데이터만 확인했으며, 지정 스프레드시트 런타임이 제공되지 않아 내부 셀을 직접 열지 못했다. 행 단위 판단은 동일 후보의 JSONL 표시 필드에 근거한다.

## 의사결정 요약

- 검토필요 15건 중 현재 이름 승인 권고: 6건
- 업무 소유자 확인 필요: 9건
- 검토필요 밖에서 추가 확인이 필요한 DM: 2건
- 전체 표기 검사: 비-ID 영문 0건, 슬래시 0건, 공백 0건, 숫자열 불일치 0건
- `row-250`의 `2회차보험기간적용보험료`는 승인 권고

## P1 — 배포 전 업무 의미 확정

### 1. DM 채널 정의 확정

- 대상: `row-150` 우편물수신여부, `row-154` 마케팅우편물수신여부
- 위험: DM이 Direct Message이면 현재 이름은 다른 채널을 의미한다. Direct Mail이더라도 단순 우편물은 범위가 넓다.
- 최소 질문: **CUS_CTM의 DM은 물리적 직접우편, 디지털 개인메시지, 또는 양쪽 중 무엇인가?**
- 조치:
  - 직접우편이면 현재 이름을 유지하거나 `직접우편물수신여부` 계열을 검토한다.
  - 개인메시지이면 `개인메시지수신여부` 계열로 두 행을 함께 변경한다.

### 2. 차량 식별자 값 도메인 확인

- 대상: `row-169` 차대번호
- 위험: 실제 임시번호 값이 존재하면 소비자가 모든 값을 차대번호로 오인한다.
- 최소 질문: **이 컬럼에 임시번호가 실제로 저장되는가?**
- 조치: 항상 차대번호이면 유지하고, 임시번호가 존재하면 두 값을 포괄하는 승인 용어를 업무 담당자가 정한다.

### 3. 구좌와 계좌의 업무 개념 확정

- 대상: `row-332` 계좌수
- 위험: 계약담보의 가입 단위인 구좌를 금융 계좌로 오해할 수 있다.
- 최소 질문: **ACT_OR_ACTCT 값은 금융 계좌 개수인가, 담보 가입 구좌 수인가?**
- 조치: 코드 정의에 따라 `계좌수` 또는 `구좌수`를 확정한다.

### 4. WKDY와 주일의 의미 충돌 해소

- 대상: `row-794`, `row-795`
- 위험: WKDY는 평일, 주일은 일요일로 읽혀 업무 의미가 반대가 될 수 있다.
- 최소 질문: **주일가족사랑은 승인된 담보·상품 고유명인가?**
- 조치: 고유명이면 유지하고, 일반 weekday 의미이면 승인된 평일 용어로 두 회차를 함께 수정한다.

### 5. RH 값과 표준 용어 확정

- 대상: `row-107` 리서스인자형태코드
- 위험: 민감한 고객 속성에서 형태·유형·구분·혈액형은 서로 다른 데이터 구조를 암시한다.
- 최소 질문: **RH_TYCD의 코드값과 승인 한글 표준어는 무엇인가?**
- 조치: 값이 양성·음성이면 `리서스인자구분코드`, 혈액형 유형이면 `리서스혈액형코드` 등을 검토한다.

## P2 — 약어·대안 선택 확인

### 6. 위촉과 개설 선택
